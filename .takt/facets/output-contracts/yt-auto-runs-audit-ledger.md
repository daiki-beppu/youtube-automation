**厳守ルール:**

- **この出力はファイルを完全に置き換える。** 応答に含めなかった行は物理的に消滅し、以後のステップから参照できなくなる。「既存の行を保持する」「他の行は変更しない」という**記述は保持にならない** — 保持したい行は 1 行残らずそのまま応答に再掲すること。差分・訂正のみの出力は台帳の破壊であり禁止。
- この台帳は追記専用。既存の ✅ 行・Findings・実行証跡は一字一句そのまま保持して全文を再掲する。要約・削除・言い換えによる縮小は禁止。
- 監査台帳表は計画レポート（01-runs-audit-plan.md）の Audit Targets と**一対一**（同じ # ・同じ行数・同じ対象名）を常に保つ。行の削除・統合・番号の振り直しは禁止。未着手の対象も ⏳ で行を残す。
- ✅ へ変更してよいのは、このステップで対象の run トレース・定義ファイルを実際に読んで監査した場合のみ。✅ を ⏳ に戻さない（単調増加）。
- 判定は OK / Finding の二値（⏳ 行は --）。OK 行にも根拠を必ず書く。**定義監査（#1〜#5）の根拠は `file:line`、run 監査（#6 以降）の根拠は run 名 + trace.md / meta.json の引用**。ファイルで示せない確認はコマンドを実行証跡に記録した上で、根拠欄にそのコマンドを書く。
- **定義監査の固定 5 対象は、乖離が無くても「何と何を照合したか」を確認結果に明記する**（無言で「OK」と書かない。照合対象を書かない ✅ は監査済みと認められない）。
- **複数 run にまたがる再発パターンは 1 Finding にまとめ、場所欄に該当 run をすべて列挙する**（run ごとに Finding を割らない — 起票単位が壊れる）。
- Finding 判定の行には F 番号を振り、Findings 節に 1 件ずつ詳細を書く。複数の問題を 1 つの F へ一括記載しない。Findings は台帳から Issue へそのまま貼り付けられる粒度を保つ。
- この台帳自身や Report Directory 内のファイル（`01-*.md` / `02-*.md` など）を場所とする Finding を書かない。Finding の対象はリポジトリの実ファイル、または `.takt/runs` の実トレースだけ。
- 「Loop Monitor 不発の疑い」節は**該当が 1 件も無くても残し、「該当なし」と明記する**（検査を実行した証明。節が無い台帳は検査未実施として差し戻される）。行は (workflow, step) 単位でまとめ、run ごとに割らない。
- 同節で**判定が「起票対象（高確度）」の行**（現行定義に step が存在し `{step_iteration}` 相当の自前上限が無い）は、同じ内容を Findings にも Category: loop-monitor で載せて起票経路に乗せる。「記録のみ」の行（自前上限あり = 二重化が機能 / 現行定義に無い）は Findings に載せない。
- Token Usage 節は最初のパスで機械集計して作り、以降のパスでは**保持する**（再集計しない。節が欠けている場合のみ補う）。Step 別は workflow ごとに消費上位 5 step まで（残りは 1 行に畳んでよい）。
- **費用の偏りを Findings に書かない** — 費用の観測は Token Usage の所見へ（起票対象にしない）。偏りの原因が根拠を示せる欠陥（例: 差し戻しループによる浪費）である場合のみ、その欠陥を Findings に書く。
- 冒頭の進捗行「監査済み: {n}/{N}」は、毎回、表の実際の ✅ 行数と一致させる。**出力を確定する前に本文の行数を実際に数え**、進捗行・集計と一致することを自己検証する。
- Status を SCOPE_COMPLETE にできるのは、進捗行が N/N に達し ⏳ 行が残っていない場合のみ。それ以外は IN_PROGRESS のまま。
