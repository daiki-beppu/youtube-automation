# スコープ外発見ポリシー

作業中に見つけた「今回のスコープ外だが放置したくない問題」を、**捨てずに issue へ逃がす**ための規律。

「ついで直しをしない」という禁止だけを置くと、発見はそのまま消える。禁止（変更しない）と受け皿（issue にする）を対にして初めて、禁止が守れる。

## 発見したときにやること

**その場で直さない。その場で issue も立てない。レポートに記録する。**

Report Directory の自分の担当レポート末尾に「スコープ外の発見」節を追記する。

```markdown
## スコープ外の発見

| #   | 発見         | 場所                 | 今回の変更との因果  | 放置した場合の実害 | 根拠                         |
| --- | ------------ | -------------------- | ------------------- | ------------------ | ---------------------------- |
| 1   | {何が問題か} | `path/to/file.py:42` | なし / あり（理由） | {誰に何が起きるか} | {再現手順 or コード上の根拠} |
```

その場で issue を立てない理由は 2 つある。作業の途中では「今回の変更と無関係」の判定がまだ確定しないため（実装を進めた結果、実は関係していたと分かることがある）。そして起票を 1 箇所に集約しないと、重複起票の照合ができないため。

## 起票の 3 条件

`spillover` step は、記録された発見のうち **3 条件をすべて満たすものだけ**を起票する。

| 条件                                                                   | 満たさないときの扱い                                                             |
| ---------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| ① 今回の変更と**因果関係がない**                                       | 因果があるなら、それは今回の修正に含めるべきもの。スコープ外に逃がしてはならない |
| ② 放置すると**実害がある**（誤動作・データ破壊・誤公開・運用の詰まり） | 実害を書けないなら、それは好みの問題。破棄する                                   |
| ③ **根拠を示せる**（再現手順、または該当コードの引用）                 | 推測で立てた issue は、着手時に調査からやり直しになる。破棄する                  |

**破棄も記録する。** 何を捨てたか・なぜ捨てたかを残さないと、次の走行で同じ発見が同じ判断を繰り返す。

**レビューの「非ブロッキング指摘」節は ① を適用しない。** 収束ポリシーにより「今回の修正必須にはしない」と判定済みの指摘であり、因果があってもスコープ内へ引き戻さない。② ③ だけで仕分けて起票または破棄する。

## 起票するときの規則

- 起票前に `gh issue list -R daiki-beppu/youtube-automation --state open --search "<要約>"` で**重複を照合する**。既存があれば起票せず、既存 issue にコメントで観測を足す（タスククローンには remote が無いため `-R` を省略すると解決に失敗する）
- 1 発見 = 1 issue。複数の発見をまとめない（着手単位が壊れる）
- issue 本文には、発見時のレポートから **場所・実害・根拠**をそのまま転記する。「調査してください」だけの issue を立てない
- 起票した issue 番号を、この workflow のレポートに記録する。PR 本文からも参照する

## 禁止

- 発見を理由に、今回の変更へ「ついで直し」を混ぜること
- 起票を理由に、**今回のスコープ内の問題**を先送りすること（要件 ID を持つ問題は今回直す。逃がすのはスコープ外だけ）
- 「後で見る」とだけ書いて、レポートにも issue にも残さないこと
- 起票の代わりに TODO コメントをコードへ埋め込むこと
