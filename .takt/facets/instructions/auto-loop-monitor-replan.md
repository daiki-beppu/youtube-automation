plan → test_design → design_review のループが {cycle_count} 回繰り返されました。設計レビューが計画そのものを否定し、再計画に戻る流れが繰り返されています。

Report Directory 内の実装ブリーフ・実装計画・テスト設計・設計レビューレポートを確認し、再計画が収束しているかを判断してください。

**判断基準:**

- 各サイクルで曖昧さが減っているか。要件 ID の対応表が具体化しているか
- 同じ blocker・未決定事項が繰り返し再計画の原因になっていないか
- 再計画の原因が **実装ブリーフの情報不足** に帰着していないか
  - 帰着している場合、計画をやり直しても解けない。issue の側に未決事項が残っており、intake の判定が甘かったということである → **打ち切る**
- 再計画の原因が **規約文書との衝突** に帰着していないか
  - 帰着している場合、規約文書の改訂の是非は人間の判断であり、workflow 内では決着しない → **打ち切る**
- 設計レビューの指摘が毎回異なる観点から出ているか
  - 観点が毎回変わる（叩けば何か出る状態）→ 計画の粒度が粗すぎる。**もう一度だけ計画へ戻す**価値がある

**打ち切り（ABORT）を選ぶ基準:**

新しい進捗がなく、かつ原因が「issue の未決事項」または「規約文書との衝突」に帰着するなら打ち切ってください。どちらも workflow 内では解けず、人間が issue または規約文書を直す必要があります。

打ち切るときは、**何が決まれば再開できるか** を報告に明記してください。人間が次に何をすればよいかが分からない打ち切りは、単なる失敗と同じです。
