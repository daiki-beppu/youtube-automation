変更された文書・スキルが **本リポジトリの記述規約に整合しているか** をレビューしてください。

他のレビュアーの有無を前提にしないでください。記述と実態の一致（コマンドの実在・リンク切れ等）はこのレビューの担当外です。

## 手順

1. 文書変更計画（`{report:docs-plan.md}`）と今回の累積差分（変更された文書・テスト）を確認する
2. Knowledge の Source Path を Read で開き、規約文書の本文を全文取得する。要約や記憶で判定しない。検査対象は `docs/skill-design/skill-authoring-guidelines.md`、リポジトリルートの `CLAUDE.md`、`docs/development.md`
3. skill（`.claude/skills/`）が変更されているなら、skill-authoring-guidelines と照合する:
   - **必須 3 点**（外部世界に由来し、判断に委ねられない）: ①不可逆・外部反映操作の承認ゲート ②前提の存在ガード ③配布先で解決できる参照（`docs/skill-design/` は配布されない。SKILL.md から参照してよいのは `references/`・他スキルの `references/`・配布対象の docs のみ）
   - **段階的開示**: SKILL.md は入口。生成・検証ロジック、長い対照表、プロンプトテンプレート、トラブルシュート事例が本体に増えていたら `references/` へ移す指摘を出す
   - **必須 3 点以外の項目は、今回変更されたスキルに対してのみ適用する**。既存スキルの一括改修を要求しない（guidelines「適用方針」）
4. frontmatter を検査する: `description:` が double-quoted string か。`uv run yt-skills lint` を実行して確認する（読み取りのみの検証コマンド）
5. CLAUDE.md 記載規約と照合する: スクリプト配置（skill のスクリプトは該当 skill の `references/` 配下。ルート直下 `scripts/` 禁止）、実コード扱いのパス（`.claude/skills/` / `.claude/CLAUDE.template.md`）変更時の `CHANGELOG.md` `[Unreleased]` 更新
6. 契約テストが緩和・skip・削除で「同期」を装っていないかを差分で確認する

**これは {step_iteration} 回目のレビューです。** Policy の収束ポリシーに従ってください。ブロッキングにできるのは、未解消の既出指摘と、規約文書の決定への違反を本文引用 + file:line で示せる新規指摘だけです。

## 指摘の義務

すべての指摘に **file:line と根拠規約の本文引用** を付けてください。付けられない指摘は無効です（`finding_id` を発行しない）。規約文書に書かれていない好みは指摘しません。

## 判定（2 値）

この step の判定は APPROVE / REJECT の 2 値です。逸脱に技術的正当性を認めた場合も、規約文書が未改訂のままなら REJECT とし、修正案に「規約文書の改訂を同じ差分に含める」ことを書いてください（黙って逸脱しない）。

- ブロッキングの `new` / `persists` が 1 件以上 → REJECT
- ブロッキング指摘なし → APPROVE（非ブロッキング指摘が残っていてもよい）

## 禁止

- ファイルを変更すること（指摘と修正案の提示のみ）
- 規約文書の本文を引用できない指摘を出すこと
- 変更されていない既存スキルへの一括改修要求（既存の違反は「非ブロッキング指摘」として記録し、spillover に委ねる）
- 記述と実態の一致の指摘（記述整合レビューの担当）
