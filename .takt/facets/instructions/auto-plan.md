直前の intake が出力した **実装ブリーフ**を読み、要件 ID を採番したうえで実装方針を立ててください。**この step ではコードを書きません。**

## 手順

1. **ブリーフの読み込み**: ブリーフは**この指示に添えられた直前の出力**として渡されています。「確定している決定」「要件候補」「対象外」「制約」を読む。ブリーフに書かれていない要求を足さない。
   **`intake-brief.md` をファイルとして探さないでください。** intake は callable sub-workflow であり、そのレポートは子の report namespace に置かれるため、この step の Report Directory には存在しません（docs/takt-operations.md）
2. **要件 ID の採番**: 要件候補に `REQ-<issue番号>-<2桁連番>` を振る。Policy の採番規則に従う。ここで振った ID は後段で不変
3. **規約の確認**: Knowledge の Source Path を Read で開き、規約文書の本文を取得する。今回の変更が規約文書（リポジトリルートの `CLAUDE.md` / `docs/development.md` / `docs/skill-design/skill-authoring-guidelines.md` / `docs/adr/` の有効 ADR = ADR-0013・ADR-0021）のどの決定に触れるかを特定する
4. **現状の把握**: 対象ファイルを Read / Glob / Grep で確認する。本リポジトリはメンテナンスモードの成熟コードベースであり、**「既存にならう」が成立する前提**で、既存のどの構造に載せるかを明示的に決める
5. **実装方針**: 要件 ID ごとに、変更する / 新規作成するファイルと、そこで行うことを書く
6. **規約逸脱の事前申告**: 方針が規約文書の決定から外れるなら、外れる点・技術的正当性・規約文書の改訂案をここで申告する。**黙って逸脱しない**（正当な逸脱は規約文書の改訂を要求する）
7. **リスクの洗い出し**: 実装中に判断が割れそうな点を挙げ、どう決めるかを先に書く

## 制約

- テストの置き場は **`tests/test_<対象>.py` の pytest**。対象と無関係なファイルへの分散を方針に含めない
- **チャンネル固有値は `load_config` 経由**で取得する方針にする。ハードコーディングを許す方針を立てない（`config/channel/*.json` に集約）
- **エラーはドメイン例外**（`infrastructure/errors.py`）。生の `Exception` / `KeyError` を catch する方針を立てない
- パッケージ内 import は fully-qualified（`from youtube_automation.xxx import ...`）。新規 CLI は `yt-*` prefix + entry point 登録
- メンテナンスモード（ADR-0021）の範囲外の拡張（dashboard/ + extensions/ 以外の新規 TS 実装など）を方針へ入れない。必要性を感じたら issue 化を提案する
- パッケージ操作・スクリプト実行のコマンドは Policy のツールチェーンポリシーに従って記述する

## 判定

**これは {step_iteration} 回目の計画です。作り直しの上限は 3 回です。** `{step_iteration}` が 4 以上なら、内容にかかわらず打ち切ってください。3 回作り直しても方針が定まらない issue は、この workflow で扱える範囲を超えています（docs/takt-operations.md）。

計画のやり直しは 8 方向から来ます — テスト設計が要件の曖昧さで戻した、設計レビューの `NEED_REPLAN`、設計修正が計画の前提を否定した、実装 (`draft`) の `need_replan`、実装ゲートの `needs_replan`、最終ゲートの `need_replan`、`spillover` が因果ありの発見を引き戻した、loop monitor の判定。**どの経路で戻ってきても同じラウンドに数えます。**

- `{step_iteration}` が 4 以上 → **打ち切る**。各ラウンドで立てた方針と差し戻された理由、決着に必要な情報を報告に残す
- 要件 ID がすべて実装方針に対応づいた → 次へ
- ユーザーが質問をしている（実装タスクではない） → 完了
- ブリーフの決定だけでは方針が一意に決まらない → ABORT し、何が決まれば進めるかを列挙する

やり直しのときは、**前回の計画レポートを読んでから始めてください。** 同じ方針を言い換えて再提出すると、同じ理由で差し戻されます。前回何が否定されたかを踏まえて方針を変えること。
