承認された文書変更計画（`{report:docs-plan.md}`）に従って、文書・スキルを変更してください。

## 変更スコープ宣言

実装に入る前に、計画の要件一覧から **この step で実装する要件 ID** を宣言してください。宣言にない変更は行いません。

## 手順

1. 計画の要件 ID ごとに、変更対象ファイルを変更する
2. **契約テストの追随**: 計画が列挙した契約テストを、変更後の文言に同期させる。追随とは**テストの期待値を新しい記述に合わせて更新すること**であり、アサーションの緩和・skip・削除ではない。追随したテストを実行して green を確認する:
   ```
   nix develop --command uv run pytest tests/<対象テストファイル> -q
   ```
3. skill（`.claude/skills/`）を変更したなら:
   - SKILL.md frontmatter の `description:` が double-quoted string であることを確認する
   - `uv run yt-skills lint` を通す
   - 生成・検証ロジック、長い対照表、プロンプトテンプレートは SKILL.md 本体ではなく `references/` へ置く（SKILL.md は入口）
4. 実コード扱いのパス（`.claude/skills/` / `.claude/CLAUDE.template.md`）を変更したなら、`CHANGELOG.md` の `[Unreleased]` を更新する
5. 完了前に、変更ファイル一覧を確認して計画のレーン適合が守られていること（プロダクションコードに触れていないこと）を確かめ、テスト全体を通す:
   ```
   nix develop --command uv run pytest
   ```

## 禁止

- プロダクションコード（`src/youtube_automation/` / `dashboard/` / `extensions/` / `pyproject.toml` / `.github/`）の変更。必要と判明したら**実装を続けずに止まる**（下記判定）
- テストを通すためにテストを書き換えること（期待値の緩和・skip・削除）。`tests/` に許されるのは文言同期の追随のみ
- 計画の要件 ID にない変更を足すこと（良かれと思った追加も対象）。作業中に見つけた無関係な問題は、その場で直さず「スコープ外の発見」節に記録する（Policy のスコープ外発見ポリシー）
- 規約文書から黙って逸脱すること

## 判定

- 計画の全要件を実装し、追随したテストが green → 文書レビューへ
- プロダクションコードの変更が必要と判明した → **ABORT**。何のコード変更が必要か、yt-auto-feature / yt-auto-fix のどちらへ回すべきかを報告に残す
- 計画の前提が誤っている（変更対象・契約テストの列挙が実態と食い違う）→ 計画へ差し戻す
