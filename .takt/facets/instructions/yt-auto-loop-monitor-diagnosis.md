診断レビュー ⇄ 診断修正のループが {cycle_count} 回繰り返されました。**レポートを直しても診断レビューが通らない状態です。**

まだコードは書かれていません。ここで止めた誤りは安く、通してしまった誤りは高くつきます。

## 確認すること

1. Report Directory の診断レビューレポート（`diagnosis-review.md`）を時系列で読み、**未解決 finding 数の推移**を見る
2. `finding_id` を追い、`persists` / `reopened` になっている指摘を特定する
3. 診断レポート（`diagnosis.md`）の「因果の連鎖」「対立仮説」が、サイクルごとに実質的に変わっているかを見る

## 判断基準

- **未解決 finding が減っているか**
  - 減っている → 健全。診断は精度を上げている
  - 減っていない、または同じ `finding_id` が `persists` し続けている → 非生産的
  - resolved は進むが毎サイクル新規指摘が湧いて総量が減らない → 新規指摘が「診断の無効化」の根拠（反例・観測）を持つかを確認する。根拠のない新規指摘での REJECT が続いているなら、それは収束ポリシー違反のレビューであり、診断側の問題ではない
- **指摘が「記述の不足」か「原因の誤り」か**
  - 記述の不足（file:line の追記、対立仮説の棄却根拠の追加）で埋まる → 健全。レポート修正を続けてよい
  - 「この原因では症状 S-x が説明できない」が繰り返される → **原因の特定そのものが誤っている。診断をやり直す**
- **調査の材料が尽きていないか**
  - 同じコードを読み直しているだけで、新しい観測（ログ・実測・履歴調査）が加わっていない → 診断をやり直しても同じ結論に至る。**打ち切る**
- **症状の報告が足りていないのではないか**
  - 「再現条件が確定していない」「期待動作が書かれていない」に帰着する指摘が続くなら、これは issue 側の情報不足である。workflow 内では解決しない。**打ち切る**

## 打ち切りの判断

打ち切るときは、**何が争点だったか**を報告に明記してください。

- 原因の候補として何が挙がり、どれが棄却され、どれが残っているか
- 決着に何の情報が足りないか（実行ログ、再現環境、報告者への確認事項）

この情報がないと、人間が引き取ったときに調査を最初からやり直すことになります。診断は途中まででも価値があります。
