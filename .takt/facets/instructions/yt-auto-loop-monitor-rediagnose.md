診断のやり直しが {cycle_count} 回繰り返されました。**原因を特定し直しても、レビューまたは再現テストで否定され続けている状態です。**

診断修正（レポートの手直し）では解けなかったものが、再診断へ回り、それも通っていません。

## 確認すること

1. Report Directory の診断レポート（`diagnosis.md`）を時系列で読み、**サイクルごとに原因仮説がどう変わったか**を列挙する
2. 各サイクルで、その仮説が**何によって否定されたか**を特定する:
   - 診断レビューの指摘（原因が症状を説明できない）
   - 再現テストが green だった（症状を再現できない = 予測が外れた）
3. 棄却された仮説の集合を見て、**まだ試されていない方向**が残っているかを判定する

## 判断基準

- **仮説が実質的に更新されているか**
  - サイクルごとに違う原因が検討され、それぞれ根拠を持って棄却されている → 健全。探索は進んでいる
  - 同じ仮説を言い換えているだけ（表現を変えて再提出している）→ 非生産的
- **否定の理由が一貫しているか**
  - 毎回「症状 S-x が説明できない」で落ちるなら、その症状が鍵である。**S-x に絞った調査が行われているか**を見る。行われていないなら、まだ打つ手はある
  - 毎回違う理由で落ちるなら、診断の質そのものが低い。モデル・調査手順の問題であり、繰り返しても改善しない
- **再現テストが green だった回があるか**
  - 予測が外れている = 因果の理解が根本的に違う。それでも同じ系統の仮説を出し続けているなら、**探索範囲が狭すぎる**
- **調査に使える材料が残っているか**
  - 未読のログ、未実行の再現手順、未確認の依存ライブラリの挙動が残っている → 続ける価値がある
  - すべて読み尽くし、外部要因（報告者しか知らない実行条件、再現できない環境）に帰着する → **打ち切る**

## 打ち切りの判断

打ち切るときは、次を報告に明記してください。人間が引き取る前提の引き継ぎ資料になります。

- **棄却された仮説の一覧と、それぞれの棄却根拠**（同じ調査を繰り返させないため）
- **説明できていない症状**（どれが鍵か）
- **決着に必要な情報**（実行ログ / 再現環境 / 報告者への確認事項）
- **再現テストの状態**（書けたか、red になったか）

**「原因不明」とだけ書いて打ち切らないでください。** どこまで絞り込めたかが、次の調査の出発点になります。
