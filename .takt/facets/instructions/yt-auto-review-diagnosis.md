**原因仮説が症状を説明できているか** だけをレビューしてください。まだコードは書かれていません。誤った原因のまま先へ進めば、テストも修正もすべて無駄になります。

他のレビュアーの有無を前提にしないでください。規約整合性・テスト設計の品質はこのレビューの担当外です（回帰テスト設計が**予測を検証する形になっているか**だけは、この step でも見ます）。

## 手順

1. Report Directory の診断（`diagnosis.md`）を Read で開く
2. **症状の網羅**: 列挙された全症状に対し、原因仮説が説明できているかを 1 件ずつ判定する。説明できない症状が残っていれば差し戻す
3. **因果の連鎖**: 入口から症状までの各段が `file:line` で示され、飛びがないかを確認する。**示された行を実際に Read で開いて、書かれているとおりの因果が成立しているかを検証する**。レポートの記述を信じない
4. **対立仮説**: 同じ症状を説明しうる別の原因を、**あなた自身で最低 1 つ立てる**。診断レポートに挙がっている仮説の引き写しではなく、独立に考える。立てた仮説が診断で棄却されているか、棄却根拠が観測に基づくかを判定する
5. **予測の検証可能性**: 各予測が「入力 X → 症状 Y」の形で、再現テストとして書ける粒度になっているかを判定する。「正しく動く」「エラーにならない」のような粒度は差し戻す
6. **対症療法の検出**: 修正方針が因果の連鎖のどこを断つかを確認する。末端（症状の出口）を塞ぐだけの方針、または「値を検査して弾く」だけで原因が残る方針は差し戻す
7. **影響範囲**: 修正箇所に依存する呼び出し元が洗い出されているかを、自分でも Grep して確認する。漏れがあれば指摘する

**これは {step_iteration} 回目のレビューです。** 再走査の対象は **全症状 × 原因仮説の説明関係**です。Policy の再走査ポリシーと収束ポリシーに従ってください（2 回目以降の新規指摘は、診断の無効化を示せるものだけがブロッキング）。

## 差し戻す条件

- 因果の連鎖に飛びがある（「〜が影響して」「〜のため」で 1 段飛ばしている）
- 原因が「〜の可能性が高い」「〜が怪しい」で確定していない
- 対立仮説が立てられていない、または棄却根拠が推測にとどまる
- 説明できない症状が残っているのに、その扱いが書かれていない
- 予測が再現テストとして書けない粒度
- 修正方針が対症療法（原因が残ったまま症状だけ止める）
- 再現テストが「修正後に成功する」だけで、**修正前に失敗する条件**が書かれていない

## 判定の 3 値

| 判定            | 条件                                                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| APPROVE         | 原因が特定され、対立仮説が棄却され、予測が検証可能                                                                                         |
| REJECT          | 記述の不足・誤り。**レポートの修正で解消できる**                                                                                           |
| NEED_REDIAGNOSE | 原因の特定そのものの誤りを、観測（説明できない症状・棄却根拠を欠く対立仮説・予測と矛盾する事実）で示せる。**レポートを直しても解消しない** |

NEED_REDIAGNOSE は診断のやり直し回数（上限 3、超過で ABORT）を 1 消費する。誤りの観測を引用できないなら REJECT（レポート修正）に留めること。

## 禁止

- 修正方針の設計としての良し悪しを論じること（責務配置・命名・構造は他レビュアーの担当）
- 診断者の調査量を評価に混ぜること（長い調査でも因果が繋がっていなければ差し戻す）
- コードを書くこと、レポートを直すこと（この step はレビューのみ）
- TS 版（tayk リポジトリ）の実装との差分を根拠にすること
