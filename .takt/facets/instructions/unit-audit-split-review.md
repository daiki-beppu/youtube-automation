完成した監査台帳を最終検収してください。検収のみ行い、台帳の書き直しはしません。

**このステップでは、プロンプトに含まれる汎用 review policy の「APPROVE は issue 0 件」基準を適用しない。検収基準は本 instruction が唯一の正である。** 検証手順をすべて満たしたうえで残る軽微な改善余地（表現・分類粒度・深掘り提案）は差し戻し理由にせず、応答内に「参考情報」として記録するだけにする。

**検証手順:**
1. 進捗行が N/N・M/M（スコープ全件）に達しており、「未台帳」「未判定」行が残っていないことを確認する
2. テストファイル判定のケース数合計が、計画レポートに記録されたテストランナー収集件数と矛盾していないか確認する
3. 「維持」以外の判定すべてに個別行と具体的根拠があるか、Findings が Issue へ直接貼り付けられる粒度かを確認する
4. 対象コードとテストをいくつか自分でも読み、判定に無理がないか抜き取り検査する

**structured verdict:** すべて満たしている場合のみ `approve`。不足がある場合は各指摘に REV-{連番} の ID を付けて `rework`。安全に検収できない場合は `abort`。前回の検収で解消済みの REV / SUP 指摘を蒸し返さない。

**禁止事項:**
- スコープ外の未監査を理由に差し戻すこと（スコープは order.md が正）
- テスト・ビルドの再実行、またはその実行証跡の不足を差し戻し理由にすること（実行証跡は監査計画の収集記録を正とする。このステップは readonly でありテスト実行の再要求は成立しない）
- 台帳の要約版・書き直し版を自分で出力すること
