# リリースノートのコンテンツ契約

`docs/release-notes/<tag>.md` を、運営者向けに翻訳した公開リリースノートの正とする。ファイル名は GitHub Release のタグと一致させる。

## Frontmatter

各ファイルは次のキーだけを持つ YAML frontmatter で始める。

| キー | 値 |
|---|---|
| `title` | 詳細ページとサイドバーに表示するタイトル |
| `version` | GitHub Release のタグ文字列 |
| `released_at` | 公開日を表す `YYYY-MM-DD` |
| `kind` | Python 本体は `main`、Chrome 拡張は `extension` |
| `summary` | 一覧に表示する、改行を含まない要約 |
| `sidebar.order` | 新しい公開日ほど先に並ぶ負の数。日付が同じ場合は本体を拡張より先にする |

## 本文

ページタイトルは frontmatter の `title` だけに置き、本文を同じレベル1見出しで始めない。本文には `30 秒サマリー`、`アップデート方法`、`新機能`、`改善`、`直った不具合`、`詳しい変更内容` の見出しを、この順序で置く。必要な場合は「移行作業」や「今後のアップデート予定」を追加してよい。

読者が運用上の影響と必要な作業を判断できる表現に翻訳する。issue・PR 番号、内部関数・内部パッケージ名、特定コミュニティ向けの記号やリンクは本文へ出さない。本文全体をコードブロックで囲まず、見出し、リスト、強調、リンクとして表現する。「アップデート方法」の実行コマンドだけは、コピーボタンが付く `text` コードブロックで示す。「詳しい変更内容」は必ず同じタグの GitHub Release を指す。
